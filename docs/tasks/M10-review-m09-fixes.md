## 一、必须修

1. **【高】告警恢复或主人确认后再次发生，必须当新一轮处理**（[4][12][16]）：现在一小时内再发生会被并回已关闭的旧记录，告警悄悄重开，却不建卡、不写线程、不推送。鉴权告警因此让全队停摆，主人界面上没有可点的卡来解除。要做：raiseAlert 只与「仍开放」或「count>0、尚未达门槛的观测」合并；被恢复或被主人关闭（count 已清零）后再发生，一律新建告警记录（firstAt=now、count 从 1 起），随之建卡、写线程、按级别推送。syncAlertItems 加兜底：告警开放而它最新的卡已关闭、且告警 lastAt 晚于卡的关闭时间 → 新建卡。改正 `m09-alerts.test.ts` 第 124–131 行把「恢复后沿用旧 id」当预期的断言。端到端测试：鉴权告警 →「知道了」→ 10 分钟内再次 401 → 出现新的开放卡与一次 P0 推送，主人确认后 authBlocked 解除；额度、隔离同样各一组（时间戳顺序与倒序各一）。
2. **审批卡的动作描述必须与闸门判定的目标一致**（[6]，安全相关）：现在人话描述只取第一个非空字段，构造参数（例如 path 与 file_path 不同、cmd 与 script 不同）就能让卡片显示一个无害目标，而闸门按另一个目标分类。要做：描述与闸门用同一套取值；有多个不同目标时全部列出（「写入文件 A（另含 B）」），矛盾时标题标注「参数含多个目标」；原始参数预览优先保留路径、URL、命令字段，过长时首尾截断。测试：这两种构造下卡片标题显示闸门判定的那个目标。

## 二、日报与期望

3. **间隔型期望的首日与边界**（[0][8]）：按规格新口径实现：统计日内没有到期点（首个到期点 = max(生效时刻, 检查段起点) + everyMs 落在统计日结束之后）→「昨日尚未开始检查」。双期限分别计算。测试「当日生效、统计日内未到期且未满足 → 昨日尚未开始检查」，并更正 questions.md M09 第 2 条。
4. **落空事实优先**（[5]）：统计日内有该期望的落空记录就写【未出现】，不被之后改期望、暂停再恢复带来的新生效时刻覆盖。测试：周五 08:21 落空 → 周五 10:00 暂停、10:05 恢复（或下午改期限）→ 周六日报仍是【未出现】。
5. **原样重存不改生效时刻**（[7]）：新旧期望的 text、everyMs、byLocalTime、weekdays 都相同时沿用旧的 effectiveAt、lastMissedAt 与当天满足事实。测试：同日已满足后原样重存，08:21 不报落空。
6. **everyMs 等于检查段也要拒绝**（[1]）：拒绝条件改为 everyMs ≥ L×24 小时。改正 `m09-expectation-lifetime.test.ts` 第 70、77 行的等号正例，更正 questions.md M09 第 3 条。
7. **日报时区测试补上海以东**（[13]）：加 Asia/Tokyo 用例，能区分「跟随设置」与「写死上海」。

## 三、给主人看的文字

8. **复盘、恢复补排等候选给主人摘要**（[2][11][18]）：shouldReflect 三种触发、resumeOwnerMessages、light_check、catch_up、deadman 重试等候选都要有面向主人的摘要（例如「按你的纠正做一次复盘」「连续两次没交账，做一次复盘」「本周例行复盘」「继续处理你暂停期间留的消息」）；ownerReasonSummary 对没有主人摘要的旧候选给保守的主人文案。测试断言这些路径下状态栏、唤醒记录、活动流不含「请…」这类写给机器人的指令。
9. **审批后的状态说法要跟着实际进展走**（[17]）：「你批准了：…，中心会在下次巡检时执行」只在队友在岗（active/probation）时出现；出站执行完以后，状态与唤醒记录改成「已执行你批准的：… → 成功/失败」；队友暂停时写「你批准了：…，队友恢复在岗后由中心执行（24 小时内有效）」；队列合并多项决定时写「处理你的 N 项审批：…」；批准因暂停过期未执行时，线程说明「批准已过期，未执行：…」。
10. **出站失败要说清原因、不谎称已执行**（[3][9]）：执行前复查被拦下写「未执行你批准的：<动作>（原因：<中心判定的原因>）」；执行失败写「已执行你批准的：<动作> → 失败：<一句原因>」，原因只用中心自己产生的（FsIO 错误首句、分类理由、超时/连接失败等短语），不转述外部返回正文。
11. **结果说法格式统一**（[19]）：「<动作> → 已完成」「<动作> → 执行失败：…」，与线程结果消息共用一套格式。
12. **日报不出现内部代码与原始参数**（[20]）：额度灯用中文标签（与 overview 的 lightLabel 一致）；「未单独推送」只列卡片标题，不贴正文与原始参数。
13. **额度保护的时间说法不能过期**（[21]）：用绝对时间（「11月4日 19:14 后继续」），或在展示时按当前时刻重新格式化；redUntil 已过时改成「等待一次试运行」之类的说法。
14. **宿主审批类告警不露 DSH 工具名**（[22]）：正文用工具的中文说法（运行命令、写入文件、修改文件…），宿主原文放末尾供核对。
15. **审批被拒绝或过期时，唤醒包仍给机器人原句**（[23]）：只有出站真正执行过（done/failed 且审批已 used）才省略原句；补一条 submitOutbox → 过期 → tick 的测试。
