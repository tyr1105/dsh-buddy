# M11 维护卡：装机前回归审查的 5 个中等问题

- 负责方：Codex
- 允许修改：`packages/core/src`、`packages/core/test`、`docs/progress/M11.md`、`docs/questions.md`（只追加）
- 前置：在 M10 的成果上继续（同一份副本）。规格已由总控补充：第 5 节阈值表「告警」行（额度告警何时算再发生）、第 6 节 tick 第 4 步（weekdays 时 everyMs < 24 小时；满足时间与落空归属按真实发生时间）。以规格为准。
- 依据：`docs/reviews/M10-review.json`，下文 [n] 是 `confirmed[n]`，每条有复现脚本、证据与修法（复现脚本在总控草稿 review-m10/ 下，可读不要改）。每条都补「改坏即失败」的测试，并用复现脚本的场景写成端到端测试。

1. **【中】额度红灯期间不能反复报警**（[0]，M10 引入）：现在主人在红灯期间点「知道了」后，之后每个回合正常结束（主人在 DSH 里直聊、其他队友在途回合交账）都会新建一条额度告警、一张卡、一次 P0 推送（免打扰也推），正文一模一样。要做：把「让队友休息、刷新文案」与「报告额度故障」拆开；额度告警只在真正转入红灯（宿主报额度错误、用量转红）或红灯后再次报额度错误时触发；回合正常结束只刷新状态；试运行因非额度原因失败只延长期限、刷新已开放告警的正文，不开新一轮。测试：红灯 → 主人点「知道了」→ 主人直聊回合结束、另一队友在途回合正常结束、试运行网络错误 → 都不新增告警记录、卡片与推送；保留「确认后真实 429 是新一轮」的用例。
2. **【中】有星期限制的间隔型期望**（[1]）：weekdays 不为空时 everyMs 必须小于 24 小时，≥ 24 小时用中文拒绝并提示「每个检查日一份请用 byLocalTime（例如每天 08:20 前）」；四个入口（hub_watch_propose、createBot、upsertWatch、反思交账）一致；hub_watch_propose 的 description 里补一句这个用法提示。落空归属到期点所在的本地日：感知或期望记录里保存 dueAt，日报按 dueAt 归属，凌晨补报的旧欠期不算到新的一天。测试：工作日 + 24h 被拒；工作日 + 12h 周一漏跑当天就报、周二日报写周一【未出现】、周三日报不受影响。
3. **【中】满足时间按事情真实发生的时间**（[2]）：DSH 关了一整天，那天日志照常写出，重启补扫时满足却记在重启时刻，次日日报对那天写【未出现】。要做：在线事件用该批变化最早发生的时间（pending.firstAt）；重启补扫出的离线变化用文件修改时间（不晚于 now）；markWatchSatisfied 与 expectation_satisfied 审计都写这个时间。测试：周四 20:00 停到周六 09:00，周五 08:10 写了日志 → 周六日报写「已出现」；周五没写 → 写【未出现】。
4. **【中】免打扰推迟的重要汇报在日报里要有内容**（[3]，M10 引入）：日报「未单独推送」里，汇报类写成「<队友名>的汇报：<正文首句，最多 60 字>（免打扰已推迟）」；审批类继续只写动作描述，不带原始参数。改正 m10-digest-owner-text 中「正文不得进入日报」的断言（按推送类别区分）。测试：凌晨推迟的重要汇报出现在当天日报里，带队友名和首句。
5. **【中】复盘期间批准的出站动作不能作废**（[4]，基线就有）：复盘回合进行期间，已批准的出站单只推迟，等复盘结束再执行，不判失败；approval_decided 候选不并入 reflection 变体（复盘照常排队，审批结果另起一轮或排在复盘之后）。改正 m10 测试里把「批准合入复盘后判未执行」当预期的断言。测试：批准时队友正在复盘 → 复盘结束后动作执行成功，线程写「已执行你批准的：… → 已完成」。
