# 疑问与默认做法

实现方（Codex / DSH）遇到任务卡没写清的地方，在这里记一条：卡号、问题、你采用的保守默认、理由。总控会逐条看。

## C01（2026-11-05）：采用的保守默认与接口约定

1. **依赖版本冲突**：根守则写 zod 3，任务卡明确 zod 4，现有 core 依赖也是 zod 4。按任务卡和已安装依赖实现，不安装或升级任何依赖。
2. **试岗窗口预算及补课上限**：规格仅举每日预算减半的例子，未单列窗口减半的取整方式；按“试岗减半”应用于全部预算，回合数向下取整，默认每窗口 3 → 1 回合。`catch_up` 未单列回合上限，沿用 regular 的 30 步 / 20 分钟 / 60000 token。以上均可通过 Settings 对应数值覆盖。
3. **路径、时区及日志器**：`Settings.rootDir` 保留规格的 `~/AgentHub`，core 不读取用户环境；宿主须展开成绝对路径再传给 `FileStore` / FsIO。`FsIO.list` 返回直接子项名称。FileStore 的 `tz` 参数决定日志日期，默认使用配置的 Asia/Shanghai；另有可选第五参数 Logger（缺省 ConsoleLogger）、第六参数保留期设置，四参数用法保持可用。
4. **存储查询与加载**：Table.get 不存在返回 null；读写均复制记录，修改必须通过 put/patch，patch 禁止改 id。recent 从新到旧，since/all 从旧到新，同时间保留追加顺序；since 包含边界。load 是启动恢复操作：有未落盘更改时拒绝加载，加载期间拒绝业务写入。单条表记录只按任务卡检查对象和非空 id，不用最新领域 schema 丢弃旧版记录。
5. **保留期口径**：记录严格早于截止毫秒才删除；wakes 优先 endedAt，其余关闭记录优先 answeredAt / usedAt / decidedAt / doneAt，缺少关闭时间才退回 startedAt / createdAt；没有可靠时间则保留。approved 审批仍可使用，不视为关闭。内存日志只留最近 14 天，磁盘按各日志保留期保存；截止日整天保留，只删除更早的日文件，备份和未知文件名不自动删除。
6. **追加失败恢复**：规格未说明 append 部分成功后抛错。每个日文件由单个 FileStore 独占写入；追加前留原文快照，失败后备份现场并原子恢复，再保留待写行供重试；恢复也失败时，后续 flush/prune 先恢复再继续。损坏 JSONL 行跳过并备份，无换行尾部先补分隔换行。该策略不提供跨进程多写者协调。
7. **子进程输出过量**：任务卡要求 execFile 且输出有界。采用 Node 的 maxBuffer 对 stdout/stderr 分别限制 maxOutputBytes，超量会终止进程，返回 code=null、timedOut=false 及完整 UTF-8 前缀；真正超时返回 timedOut=true。避免为了继续运行而无限缓存输出。网络与进程原始输出不附加文案截断标记。
8. **纯工具未指定的边界**：DST 不存在的本地时刻拒绝，重复时刻解析取较早实例；nextLocalTime 严格晚于 afterMs，可取重复钟点的第二次，并跳过不存在钟点。truncateBytes 的预算放不下完整“已截断”标记时只保留标记的可容纳前缀。lineDiff 的比例为新增与删除行数之和除以行集合并集大小。stddev 用总体标准差；空集、单值和零均值的变异系数为 0。stableStringify 去掉对象及数组中的 undefined，根 undefined 表示为 null，非 JSON 值及循环引用明确报错。

## C02（2026-11-05）：感知、调度与健康的保守约定

1. **新增数值配置**：第 6 节公式与任务卡的小参数集中在 `config/defaults.ts` 的 `C02_DEFAULTS`，通过 `Settings.c02` 深合并覆盖；心跳进程号 `heartbeatPid` 由宿主传入（默认 null），`hostDownAfterMs`、`deadmanAlertCooldownMs` 单列。没有读取系统进程或增加依赖。
2. **关注项状态容量**：`Watch.lastValue` 使用不超过 4 KB 的合法 JSON，保存正文、已见条目短指纹、退出码或文件大小，以及 `lastError`、`consecutiveFailures`。HTTP 的完整内容指纹不截断，差异正文受 4 KB 上限影响；目录大小基线也在容量不足时淘汰旧路径。它们是有界摘要，不是完整内容历史。
3. **RSS 长列表**：最小 RSS/Atom 解析只比较当前 feed 前 200 条，当前条目优先进入已见缓存，历史补足。这样不会因为超过 200 条而每次把淘汰的旧条目误报为新条目；更早条目不在本期观察范围内。
4. **文件路径与离线补扫**：glob 只允许当前目录末尾 `*.扩展名`，普通目录递归，其他通配形式拒绝并记录关注项错误。`syncFileWatches` 在恢复已有基线时比较 mtime、大小及消失路径，把离线变化放入同一个两分钟批次；首次注册仅建基线。`flushFileEvents` 遍历批次快照，读盘失败保留批次供下一次调用重试。
5. **日志追加与期望满足**：按 UTF-8 字节大小读取新增尾部；截短视为轮转后新内容，同尺寸重写不算追加。新增内容包含换行才更新 `lastSatisfiedAt`，避免把半行写入当作一次完整的预期更新。
6. **脚本路径边界**：只执行拆分后的程序与参数，不使用 shell；白名单按任务卡，node/python3 必须直接指向家目录脚本，拒绝内联代码入口。路径校验使用规范化绝对路径与目录边界；现有 FsIO 没有 realpath/lstat，无法独立验证符号链接最终目标，宿主须保证家目录脚本不通过符号链接越界。
7. **感知时间与门槛**：`createdAt` 是中心实际记录时刻，用于 24 小时去重；输入 `occurredAt` 只决定紧迫度。新奇度独立检查同一关注项的一小时历史，不依赖可覆盖的去重窗口。日志门槛从当天账本计算疲劳，不依赖可能尚未刷新的 DriveState。
8. **候选与变体合并**：Candidate 是 QueueEntry 去掉 id/enqueuedAt。理由取最高分，等分取更高优先级，防止主人消息被旧感知主体遮蔽。普通变体 regular > catch_up > light_check；trial/teach/reflection 互遇时保留先到的特殊变体。证据去重合并；所有已处理感知的事项键都会记入冷却。轻复查按规格豁免分数门槛；trial/teach/reflection/catch_up/retry 采用各自触发条件，也交由九道闸控制。
9. **唤醒单最小扩展**：新增可选 `subjectKey` 与 `dispatchedAt`。C04 建单时应写 `dispatchedAt=null`，成功投递后写真实时刻，并从 QueueEntry 复制主体。明确未投递的失败不进入六小时冷却，也不计为三次回合错误；旧记录缺省时从证据恢复主体，缺少投递标记只能保守推断。合并证据的其他主体也会冷却。
10. **错误次数两种口径**：任务卡第 4 次投递/重排失败隔离，与默认表连续 3 次真实回合出错并存。scheduler 处理四次重排；health 检查最近三张真实已结束的 error/timeout 唤醒单，排除未投递与未来终态。连续两次未交账后，最近一次 reflection 仍 no_commit 才触发对应隔离。
11. **内驱已处理与暂缓**：问题等待只认已过期、已填写默认答案及 answeredAt 的提问；有更新的交账就不再为旧答案触发。每种内驱取最强事项，按分数使用每日名额；24 小时暂缓以种类为键，不能换目标绕过。新 progress 清零内驱值快照，但保留当天次数与暂缓时间。
12. **轻复查锚点及关注项寿命**：轻复查锚定 lastThinkAt，无思考历史时使用 createdAt，不能每个 tick 把它往后推。若覆盖配置使 pace_min 大于 pace_max，夹紧时以 pace_max 为上界。机器人自建关注项缺失 expiresAt 时按 createdAt + botWatchExpiryMs 过期；主人与中心关注项不自动撤销。
13. **额度与计量口径**：没有回合时只返回默认额度快照，不提前建立窗口；第一次记账从当前及其他未结算、已实际投递的回合取最早开始时间。主人发起回合排除个人自主预算，但真实消耗仍计入全局额度。估算或宿主 token 乘 1.2 后向上取整；同 wakeId 幂等记账，不重复扣用量。
14. **红灯恢复协议**：普通 rollWindow 不解除红灯。`maybeAllowProbe` 到期授予一次许可；C04 投递前调用新增的 `consumeProbe` 原子消费，红灯且 redUntil=null 表示探针在途；仅该状态接受 `onProbeResult`，没有在途探针的结果明确拒绝。成功转绿，失败再等一窗口加宽限；探针仍经过预算、并发等闸门。
15. **告警观测与合并**：首次保存 closed/count=1，第二次 open；一小时内复用记录，跨一小时新记录继承尚未恢复的连续次数并关闭旧 open 记录。`closeAlert` 清零次数，后续故障重新累计。deadman/quarantine 已由独立触发规则确认，直接 immediate；否则二次门槛会与六小时限频冲突。带显式 now 的调用也把该时刻传入告警，避免两种时钟漂移。
16. **补课与心跳**：收集补课候选后将 Downtime.handled=true，避免重复收集；C04 负责将返回候选入队。retry/catch_up 未指定分数，采用可配置的 0.75/0.50。心跳写入失败不消耗节流机会，损坏心跳保留并记录警告，不捏造停机时长。
17. **组装边界**：本卡提供计算与决定，不实现实际投递、取消会话、主人红灯系统消息、完整 tick、交账后清零或文件刷盘编排。这些按任务卡属于 C03/C04；`selectNext` 不移除通过项或消耗探针。选择前会滚动过期普通额度窗口，使事件入口不必等下一次 tick。
18. **并行规格变化**：执行期间观察到 build-spec 6.5 新增防议程“拼周期”条款，明确在 `hub_agenda_upsert` 校验；C03 任务卡同步点名该要求。本卡未实现工具入口，也未修改或回退该规格、C03 任务卡及第 11 节并行变化。

## C03（2026-11-05）：醒来后的交互与安全边界

1. **异步接口与工具身份**：涉及 FsIO、HostPort 的包构建、回合处理、交账、审批、出站、记忆和套路接口返回 Promise；`buildWakePacket` 为 Promise<string>。ToolContext 固定为 `{botId, sessionId, wakeId: string|null}`，由宿主提供，不从模型参数推断身份。handler 本身也执行校验与权限检查，不能绕过 runTool。未在岗机器人不能使用变更工具。
2. **交账与宿主终态分开**：hub_commit 先原子保存 commitId/status=committed，但 endedAt 保持 null；此时仍占并发，直到宿主 ended/error/cancel 才记用量和释放。WakeTicket 新增可选 ownerDirect、tokensKnown、awaitingApprovalAt、syntheticCommit，兼容 C01/C02 老记录。重复终态只记一次账；await 文件核验后重读交账状态，避免并发真实交账被误标 no_commit。
3. **主人直聊不交账**：规格允许交账可选，而 WakeStatus 没有单独的 ended 值；直聊结束无交账时用 no_commit 表示“没有交账记录”，但不合成 no_change、不增加连续未交账次数。依然计入全局真实消耗，豁免机器人自主预算，最终文本进入线程。主动唤醒未交账则按卡合成；给主人缺回复的提示来自 hub，不冒充机器人回答。
4. **相关目标如何确定**：优先认交账/唤醒证据中的 goalId，或所引用议程的 goalId；没有明确关联且只有一个 active/blocked 目标时才默认关联它，多目标不批量认领进展。反思没有显式目标证据时不使用该默认，保存教训不等于目标有进展。done 只转 done_pending_check，主人验收默认“未通过”，超时或否定恢复 active。
5. **交账后的部分 I/O 失败**：先保留唯一交账与领域结果，再分别尝试保护核对、结果路由、日志和视图刷新。失败记录 commit_effect_error 审计，并在工具文字里明确提示；不撤销真实交账或重放已完成副作用。通知失败不能阻止收件箱/提议保存；文件核验失败不能阻止终态记账。未声称已经写入失败的文件。
6. **包内信任与截断**：外部摘要的信任不会因进入理由、证据或同伴议程而提升；理由与证据默认围栏，原感知被清理后也保持不可信。主人原话从 owner 线程单独恢复。多行议程/证据压成单条展示，再按条保留前 10/5 个 id；极长字段按共同字节预算缩短。围栏先转义再计量，始终完整。覆盖配置小到连固定协议都放不下时明确报错，不交付破损协议。
7. **命令分类与授权子类**：未知语法、动态展开、无法确定的命令/参数按 C；已识别的更危险段仍按 D/protected。L3 仅支持精确子类授权（例如 write_file、http_post、git_write、send_message），不接受 `*` 或笼统 C 作为免审。工作数据未授权不能用普通批准票绕过，须先修改 workDataAllowed。protected 不走审批。包管理器的目录覆盖参数也重新分类。
8. **路径能力的实际边界**：文件工具、shell、交接均做规范化目录段检查，拒绝路径穿越；FsIO 没有 realpath/lstat，不能独立验证符号链接最终目标。宿主仍须提供实际文件权限隔离；本卡未声称 shell 静态分类可以沙箱任意用户脚本。
9. **工具等级的细分**：B 类矩阵返回 L1 需审批；具体工具按第 10.1 节细化成目标/新增关注提议、已有关注收窄与议程直接操作。hub_routine_save、hub_lesson_propose 的“全部等级”按工具表保留；反思的普通变更工具被拦，关注/教训通过 hub_reflect_commit 的明确字段处理。正则替换无法证明范围更窄时拒绝，普通关键词仅允许增加包含原词的限制。
10. **结构化提议**：L1 修改已有目标保存独立 proposed 副本，用 proposal_target 审计绑定原目标，接受后再原位替换。拒绝、七天撤回或门槛/周限额转点子池时，将对应 proposed 关注/目标/规则转 expired/abandoned/archived，保留 Inbox 文本及原 active 记录，避免占满关注配额。接受时重新检查状态、过期、归属与工作数据授权。
11. **目标与提议的日历口径**：day 到次日本地零点，week 到下周一零点，month 到下月一日零点，one_off 无周期末；L1 每周三条按本地周一开始统计。低价值/低置信度/超周限额均进点子池；被拒同标题严格小于 30 天才抑制，满 30 天允许再次提议。
12. **出站与单推**：outbox 的批准哈希绑定 `hub_outbox_execute` 和完整 `{kind,payload}`；只消费一次，执行前重新检查当前生命周期和权限。notify_owner 已写线程但通知失败时保留 done，结果明确写单推失败，避免重复汇报。普通 commit report 用机器人 id 和正文指纹作为主题，避免不同事项的 report 抢占同回合提问主题；同正文仍受 24 小时去重。
13. **追加日志与长期已读**：markRead 为异步，必须 await；除审计外，已读游标原子写入 `.hub/thread-read-state.json`，initRoot 加载，threadMessages 返回应用游标后的视图。同一毫秒通过消息 id 区分已读边界。保护核验/刷新按机器人串行，合法刷新前核对旧基线；套路同名保存也串行，防止并发产生两条记录。
14. **日报的事实源**：日报合并 commit.report 与已完成 notify_owner 出站，去重后选最重要三条，并呈现昨日直接生效的目标变更。C02 日志期望满足时补 expectation_satisfied 审计，使今早的新满足时间不会覆盖昨天事实；仍兼容旧 lastSatisfiedAt。被免打扰或预算拦住的推送、停机时长、未出现期望、周日点子池均从存储拼装，不调用模型。
15. **反思输入与失败处理**：lessons 每条为 `{text,scope,why}`；watchChanges 接受 watch_update 或 watch_propose 两种参数形状；routineUpdates 同 routine_save。先在隔离内存副本预检全部关注变更，再落实；同 wake 并发提交拒绝。若 I/O 中途失败，保留真实已完成变更与 reflection_effect_error，禁止同回合盲目重放，下一回合可处理。paceAdvice 只写审计，不改变主人配置。
16. **总管与回复候选**：真实转入隔离时补 quarantine_event 审计，总管用事件身份去重，解除后再次隔离不会被旧原因永久抑制。outbox_done 与 team_attention 的分数在 recordPercept 内一次赋值，避免事后改分使日志/退避不一致。审批结果与提问回答保证入队 priority=90，随后仍经过预算、额度及生命周期闸门。
17. **新增可配置值**：C03 的字节限额、教学摘要、报告重要度、反思阈值、五分钟审批框取消、议程十条、交接七天等集中在 C03_DEFAULTS / Settings.c03；JSON schema 的字段范围、日历枚举和单位换算不作为运行默认值。
18. **交付与 C04 接线边界**：本卡提供单模块能力，不创建 Hub/UiApi/SimHost，不连接真实 DSH。C04 调用 buildWakePacket 时须 await；需要轮换时传 null sessionId 或新 sessionId。tick 接 checkTurnLimits、expire*、shouldReflect、checkTeamSignals、executeReadyOutbox、maybeSendDigest、syncAlertItems。回合终态接 onTurnEvent/finishTurn；其余 C02 告警由 syncAlertItems 转入箱，恢复关闭。投递、感知消费、probe 归属、flush、真正的宿主取消与启动恢复编排仍按 C04 处理。

## M01（2026-11-05）：维护卡修订与边界约定

1. **执行器输出与退出语义**：M01 第 1、2 条覆盖 C01 第 7 条旧约定。stdout/stderr 各保留 `maxOutputBytes` 字节，持续读空超出部分并保留正常退出码；两流累计读取超过 `32 × maxOutputBytes` 才终止进程组。倍率集中在 `config/defaults.ts`；新结果字段 `outputTruncated` 与 `killedForOutput` 区分软截断和硬终止，`timedOut` 只代表超时。两流合计采用硬限是保守的资源限制；恰好达到硬限仍可正常结束。进程以独立组启动，超时立即结束等待；内核回收可能异步，测试在返回后用信号零短轮询确认整个组消失。

3. **JSON 写入边界**：put/patch/append 在进入存储前完成 JSON 往返；循环引用、BigInt、函数、symbol 和非有限数值直接中文拒绝。可选对象属性 undefined 按 JSON 标准省略，数组 undefined 按 JSON 标准归一化为 null，兼容既有可选字段。自定义 JSON 转换后再次校验日志时间和 patch 的 id，避免归一化结果绕过入口约束；失败不改变原记录或脏标记。
4. **坏文件备份与清理**：M01 第 5、6 条覆盖 C01 第 5 条“备份不自动删除”的旧约定。坏表先完整备份再标脏，下一次 flush 写干净表；坏日志备份后立即原子写回所有有效原行。备份按文件名中的生成毫秒数保留 30 天，准确边界保留；只清理已知表/合法日志日期的 `.bad-<时间>[-序号]`，未知命名保留。新增 `Settings.badBackupRetentionMs` 可覆盖默认值，FileStore 通过既有保留期参数接收。

6. **刷盘失败汇总**：按表、按日志独立捕获故障；失败集合保留自身脏状态，成功集合正常确认，全部尝试后统一抛出包含中文集合定位的 AggregateError。未完成的日志回滚只阻塞所属日志；失败日志器也不能阻断其他集合。

## M11（2026-11-05）：装机前回归的补充与保守默认

1. **额度“再发生”的边界**：按补充规格，只有用量真正转红和宿主新报额度错误进入告警入口。红灯期间正常收尾、非额度原因的探针失败只让队友休息并刷新仍开放的告警正文；不改变故障计数、发生时间或已确认记录。真实 429 仍按 M10 的新轮身份生成卡片和 P0 通知。
2. **更正 M10 第 2 条的星期间隔上限**：所有非 null 的 weekdays（包括全七天）均要求 everyMs 小于 24 小时；null 仍允许跨天间隔。每个检查日一份应使用 byLocalTime。新增可选 Percept.dueAt 和 Expectation.lastMissedDueAt 保存实际到期点；原 createdAt/lastMissedAt 继续表示发现时间、保留既有调度和每日限报。旧档没有到期点时无法推回精确期限，日报保守按旧发现时间归属，不改写历史。
3. **离线变化的时间证据**：在线合批取 pending.firstAt；离线补扫取变化文件的最早 mtime，并截到不晚于发现时刻。删除文件或超量快照缺少逐文件 mtime 时，无法证明更早发生时间，使用发现时刻。启动直接跳过去抖等待，不再倒改 firstAt。晚到历史事件写真实时间的满足审计，最新 lastSatisfiedAt 不倒退。
4. **更正 M10 第 7 条的延迟汇报口径**：汇报是给主人的内容，日报补队友名与正文首句；审批仍只列动作标题，不带原始参数。两条真实汇报入口均使用“机器人汇报”标题识别类别，历史机器人资料缺失时称“队友”，不显示内部 id。首句按中英文句末或换行截取，按完整字符最多 60 字；新增 Settings.c03.deferredReportMaxChars，默认 60，可收紧，旧设置由原深合并补默认。
5. **审批与复盘的排队例外**：依 M11 明确要求，同一机器人可分别保留审批与复盘候选，不再强求两者合成一条；连续未交账要求的复盘另行保留，不能被批准回合的交账清零吞掉。已批准出站单在复盘尚未 ended 时只延期，不消费票、不终结失败；复盘结束后重新走完整权限复查。原批准截止时间与暂停、拒绝、过期规则不延长或放宽。
6. **双期限补报不能丢掉第二天**：交叉回归确认，间隔的欠期在周一、钟点的欠期在周二而同时被发现时，只存最早 dueAt 会让周二后来满足覆盖当天已错过的钟点。可选 dueAts/lastMissedDueAts 因此同时保存这次实际触发的两个期限，去重升序；单值字段保留最早期限以兼容，日报对任一到期点所在日保留落空事实。仍是一条感知、原每日限报，不把一份事件拆成重复提醒。
7. **投递时的审批证据边界**：入队之外，旧混合队列和主人打断留下的 deferredByOwner 事实也会重新加入证据，因此投递前再将审批从复盘拆成常规候选。主人消息成为主理由时，审批结果节仍按真实审批证据加入，保证原参数重试指令不丢。未附批准票的非 A 出站同样暂缓到复盘结束再复查，现有 A 类规则保持。
8. **整数毫秒与原始小数精度**：真实文件系统 mtimeMs 可能含小数，现有 everyMs 正数入口也允许小数；直接写入新时间字段会被 timestamp 校验拒绝。文件修改时间用于事件时向下取整并截到 now，原始基线和 statKey 保留精度以继续检测变化。小数间隔的到期比较保持原值，仅持久化期限向下取整，不收紧既有输入范围；新增回归确认不会卡住批次或阻断其他关注项检查。


## M12（2026-11-05）：宿主命令审批、内容绑定与脚本写入沙箱

1. **L3 授权与旧票迁移**：规格 7.4 的“一律要主人批准”优先于普通 C 类的 L3 子类授权；宿主 run_command 即使匹配 host_command、run_command 或已有 C 子类授权也逐次审批，D 不降级，protected/work_data 仍硬拒绝。旧 ready 无票重新采集当前文件内容再建审批；旧待批或已批记录缺 commandFiles 时按空兼容读取，但不追认未绑定内容的旧票，作废旧票并重新审批。新批准票哈希包含 commandFiles，精确消费出站行关联的 approvalId。
2. **文件指纹与路径默认**：绑定 cmd/args 中可静态识别且实际解析到家内的普通文件，额外识别 shell 静态词、cd/env 工作目录、长短选项值、@ 响应文件和 file URL。保存原引用绝对路径、realPath 和原始字节 SHA-256；重采集整份列表，批准后新建、删除、改内容、改变链接目标或读取失败均不沿用批准。家内路径指向家外时保守拒绝；敏感路径和未授权工作数据在读正文前拒绝。无法确定普通文件类型、权限故障、路径不能可靠解析时失败关闭，不把错误当空指纹。新增 FsIO.readBytes；系统通过非阻塞、禁止跟随最终链接的文件句柄打开并验证普通文件，避免 UTF-8 替换碰撞及管道阻塞。
3. **内容失效的结果与权限竞态**：内容复查不通过写 rejected、executionStarted=false、指定“脚本在批准后被改动”原因，原批准票作废；线程、状态和重新生成的审批摘要都表达“未执行你批准的”，不伪造主人拒绝。异步文件检查前后对比权限上下文和出站记录；暂停、降级、进入复盘、工作数据授权变更或出站行变更时本轮不消费票、不运行，下一轮重新核验。提交过程中权限变化则拒绝此次建单。
4. **沙箱不可用的判定**：每次带 sandbox 的 SystemExec 调用先以同一真实路径规则执行 /usr/bin/true，不能仅凭 spawn 成功认定 Seatbelt 生效。非 macOS、目录/参数错误、缺程序、探针失败和正式沙箱启动失败均抛“当前系统没有可用的沙箱，脚本关注不运行”，从不回退普通执行。正式进程 stderr 若以 sandbox-exec: 开头也保守视为沙箱启动失败；正常脚本恰好输出此前缀可能被误拒，但不会越权。没有新增配置默认数值或依赖。
5. **真实沙箱测试的环境边界**：测试先独立运行 /usr/bin/sandbox-exec -p '(version 1)(allow default)' /usr/bin/true；仅此探针不可运行或平台不是 macOS 时允许跳过并打印原因。当前环境实际返回 sandbox_apply: Operation not permitted，因此 3 项真实隔离测试未在本环境执行。完整测试保留非临时目录的可写根、系统临时目录、/dev/null、主人家目录随机拒写及链接拒写、空格/引号/反斜杠目录与无沙箱行为，须由总控在沙箱外重跑。任务指定 scratchpad 参考文件在本副本与相邻项目未找到；规则与字符串转义按任务卡明确给出的内容实现。
6. **规格机制的保证范围**：本卡实现的是“cmd/args 可静态识别的文件内容绑定 + 执行前重新比对”，不是不可变文件系统快照。程序运行时动态计算的路径、通配展开结果、传递 import 与 PATH 依赖未自动形成完整依赖清单；其他进程在最后一次核验与操作系统装载之间的修改，也无法仅靠此接口保证原子隔离。没有把这项检查表述为消除一切跨进程 TOCTOU。进一步冻结整个执行文件树或改变批准后权限模型需由总控另定规格；本卡对脚本关注始终使用写入沙箱，对宿主出站始终要求逐次批准。

## 2026-11-06 视觉修复：主题变量名与宿主 token 不一致

- 问题：styles.css 全篇使用的 `--dsw-alias-separator / bg-inset / accent / text-primary` 等变量名，在宿主（DSH desktop）实际主题里不存在（宿主只提供 `border-l1/l2`、`bg-layer-1/2`、`brand-primary`、`label-primary/secondary`、`state-*` 等，见客户端 Theme Inspect）。变量取不到时整条 border/background 声明失效，表现为按钮无边框、无背景、hover/选中无反馈。
- 保守默认：在 `.ah-page`（及 shell.overlay 里的 `.ah-toast-layer`）上加一层旧名→真实 token 的别名映射；宿主没有的中间色（accent-muted、fill-hover/selected、scrim、阴影）用 `color-mix` 从 brand-primary / label-primary 派生，不写死十六进制，保持「只用主题 token」约束。全篇样式不逐行改。
- 理由：一处定义、全篇生效，且 DSH 未来若补齐同名 token，别名层可整体删掉。
