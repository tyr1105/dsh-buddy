# D06 进度记录：接上 core 的 M07 新接口

日期：2026-11-05。实现方：DSH，`packages/plugin`。已完整阅读根目录 `AGENTS.md`、任务卡 `docs/tasks/D06-wire-core-m07.md`，接口签名与用法以 `docs/progress/M07.md`「插件接线」一节为准。七项全部完成。

## 做了什么（按文件）

### 宿主半边（packages/plugin/src/host/）

| 文件 | 改动 |
|---|---|
| `real-hub.ts` | ① settings 异步化：`pushChannel()` 不再同步调 `hub.api.settings()`，改为缓存（构造时异步预热一次，收到 settings 范围的变化事件再刷新；读失败保持旧值、初始默认 `'dsh'`，绝不阻塞投递）；`settings()` 视图直通 core 的 Promise。② 命令表新增 `lifecycleAction` / `interruptBot`（整对象透传，UiApi 内 zod 再校验）。③ 删除 `RealHubExtras`（旧的宿主侧 interrupt 特殊分支）；订阅回调加 try/catch 兜底。 |
| `index.ts` | ① 删除 `createInterruptCommand`（D04 3b 的插件侧 cancel + 系统消息实现；core 现在自己做）与 extras 注入。② `createEngineHub` 新增第三参 `listModels?: ListModels` 并传入 `createHub`；`startEngine` 用 `createHostListModels(ctx)` 构建。③ 新增 `hubCancelMarks`：`host-port` 的 `onHostCancel` 登记「core 经 host.cancel 取消的会话」，翻译层据此区分中心取消与主人打断。 |
| `list-models.ts`（新增） | 宿主模型目录（任务卡第 6 条）：优先 `sessionController.modelCatalog()`（只保留 `routableProviders` 里的组），缺失时退回 `ctx.get('llm').listProviders()+listModels()`；映射为 `{provider, model, label}`（label 用宿主显示名，缺省退回模型 id），按 provider/model 去重；两个来源都没有或调用抛错时抛中文错误，绝不返回空数组冒充「没有模型」。 |
| `host-port.ts` | deps 新增可选 `onHostCancel`；`cancel()` 第一行登记（core 发起的取消可被翻译层识别），登记失败不影响取消本身。 |
| `turn-events.ts` | 任务卡第 2 条：turn/end 的 reason 属取消/中止族（`aborted/cancelled/canceled`，新纯函数 `isAbortReason`）时——中心发起的取消（consumeHubCancel 命中）一个事件都不发（core 已先记录 canceled/timeout）；否则翻译成 `{type:'interrupted', sessionId, at, by:'owner'}` 交给 `hub.onTurnEvent`。标记在任意 turn/end（含正常结束）消费，避免残留到后续回合误伤主人打断。文件头注释同步更新。 |
