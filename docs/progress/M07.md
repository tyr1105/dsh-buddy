## 插件接线：新增接口和兼容事项

公开接口均从 `@agent-hub/core` 导出。命令仍返回 `CommandResult<T> = { ok: true; data?: T } | { ok: false; error: string }`；宿主应显示中文 `error`。命令的 TS 参数保留 `unknown`，下面列出实际接受的 JSON 形状；非法字段、类型和枚举均经 zod 拒绝。

### 1. 主人打断

```ts
// UiApi 的公开签名；接受的 input 为 { botId: string }。
hub.api.interruptBot(input: unknown): Promise<CommandResult<WakeTicket>>;

// TurnEvent 新增这一支；其他事件保持原签名。
type OwnerInterruptedEvent = {
  type: 'interrupted'; sessionId: string; at: number; by: 'owner';
};
hub.onTurnEvent(event: TurnEvent): Promise<void>;

// 按钮直接调用；不再由插件先 cancel 或自行写系统线程消息。
const result = await hub.api.interruptBot({ botId });

// 宿主其他入口发生主人取消时，翻译为此事件。
await hub.onTurnEvent({ type: 'interrupted', sessionId, at: eventAt, by: 'owner' });
```

- 只接受 `running` / `delivering` 且未结束的唤醒单；空闲或已交账返回“它现在没在处理事情”。
- core 先同步保存 `status='canceled'`、`canceledBy='owner'`、`endedAt`，再调用 `host.cancel(sessionId)`。投递中还没有 sessionId 时立即释放投递等待，迟到创建的会话到达后再取消。
- 不合成未交账、不增加 `consecutiveNoCommit` / `consecutiveErrors` / `violations`，不由打断触发复盘或隔离；正常在岗机器人回到 `watching`。既有暂停/退役保持停止文案。已运行回合的资源仍幂等记账，未投递成功的占位不虚增用量。主人打断额度探针只归还下一真实候选的探针许可，不判定额度已恢复，也不延长红灯等待。
- core 写一次系统消息“你打断了它；它会在下次醒来时接着处理”。插件无需再补一条。
- 只恢复本回合消费的感知为未消费，保留持久评估标记并写 `deferredByOwner`；不因这些恢复事实立即重新唤醒或报掉线。下一次真实唤醒会把它们放回证据、唤醒包并再次消费。
- 为隔离没有 wakeId 的迟到宿主事件，打断时解绑工作会话；下轮创建新工作会话，机器人界面线程仍保持原 `botId`。旧 `ended/error` 即使晚于下一轮开始也不影响新回合。已取消会话的工具/宿主审批被拒绝，不再当成普通会话放行。
- `host.cancel` 失败会返回“已记录主人打断，但宿主取消失败：…”，core 的主人取消事实保持有效。此结果不代表外部操作已回滚；旧会话后续工具仍被守卫拒绝。
- 已知会话的 interrupted 可越过挂起投递先落终态；创建会话尚未绑定时到来的事件通过串行通道等待身份。普通 started/step/ended/error 的原有串行机制保持。

### 2. 生命周期动作

```ts
type LifecycleAction = 'pause' | 'resume' | 'promote' | 'release_quarantine' | 'retire';
hub.api.lifecycleAction(input: unknown): Promise<CommandResult<Bot>>;
// 实际参数：{ botId: string; action: LifecycleAction }

await hub.api.lifecycleAction({ botId, action: 'pause' });
await hub.api.lifecycleAction({ botId, action: 'resume' });
```

| 动作 | 资格与结果 |
|---|---|
| `pause` | 仅 active/probation；持久保存 `pausedFrom`，再暂停。 |
| `resume` | 仅 paused；恢复暂停前资格。试岗未结束仍 probation，即使已满三天也不暗中提前转正；暂停中试岗到期则 active，上限 L2。原正式 L3 恢复保留已有主人授权。 |
| `promote` | 仅 probation；实际试岗满三天且无越界。未满返回还差几天（向上取整），有越界明确拒绝。成功 active，上限 L2。 |
| `release_quarantine` | 仅 quarantined；清零 M03 规定的故障/越界计数并关闭隔离告警。试岗期内回 probation，实际自主权限仍受试岗 L1 上限限制；试岗结束回 active，上限 L2。 |
| `retire` | 允许从其他生命周期退役；重复退役拒绝，档案保留。 |

新增可选持久字段 `Bot.pausedFrom?: 'probation' | 'active' | null`、`Bot.probationStartedAt?: number`。旧暂停档案没有 pausedFrom 时按 probationEndsAt 推断；旧试岗档案没有实际开始时间时兼容 createdAt。新建和旧 `draft → probation` 入口均记录实际试岗起点，草稿等待时间不算三天试岗。

`setLifecycle(botId, lifecycle)` 保留，旧调用不破坏；新界面恢复、转正、解除隔离务必使用动作入口。恢复会重新安排暂停期间的主人消息。

### 3. 卡片选项与回答

线程 `card.options` 与 `api.inbox().items[].options` 使用相同约定。插件渲染并原样回传用户点击的 option。

| 类型 | options | 提交方式 |
|---|---|---|
| proposal | `['接受', '不做']` | `answerInbox(inboxId, option)` |
| approval | `['批准', '拒绝']` | `decideApproval(approvalId, option === '批准', note?)` |
| question | 机器人原 options | `answerInbox(inboxId, option)`；也接受主人非空自由文本。 |
| alert | `['知道了']` | `answerInbox(inboxId, option)`，关闭告警及卡片。 |

为使审批视图能直接接线，新增 `ThreadMessageView.card.approvalId: string | null` 与 `InboxItemView.approvalId: string | null`。审批项返回其真实审批记录 id，其他类型为 null；**不要把 inboxId 当 approvalId**。

```ts
if (card.type === 'approval' && card.approvalId !== null) {
  await hub.api.decideApproval(card.approvalId, pickedOption === '批准');
} else {
  await hub.api.answerInbox(card.inboxId, pickedOption);
}
```

proposal 接受“接受 / 同意 / 好 / accept”与“不做 / 拒绝 / 不要 / reject”，忽略大小写和空白，最终保存为“接受 / 不做”。非法值返回中文并列出合法回答；拒绝冷却、机器人详情接受率及日报统计同步支持新旧答案。旧卡片的 options/defaultOption 也在视图归一化。

旧 approval `answerInbox` 仍兼容委托唯一的 `decideApproval` 路径；新插件按上表直接调用。question 的创建仍遵守既有 2–4 个选项与默认答案约束，“自由文本”指主人可以回答选项以外的内容。

### 4. 推送范围常量

```ts
import { HUB_EVENT_SCOPES, type HubEventScope, type HubChange } from '@agent-hub/core';
// HUB_EVENT_SCOPES = { overview: 'overview', bot: 'bot', thread: 'thread',
//                      inbox: 'inbox', activity: 'activity', settings: 'settings' }
// HubChange = { type: 'changed'; scope: HubEventScope; botId: string | null }
```

| scope | 何时发送 / 插件刷新 | botId |
|---|---|---|
| overview | 中心启停、健康、额度、全队汇总；刷新 overview。 | 全局 null；单机器人变化带 id。 |
| bot | 交账、感知、议程、目标、关注、规矩、套路、生命周期、队列、回合、档案；刷新对应 bot 详情和总览卡片。 | 必带。 |
| thread | 消息、已读、内嵌卡片变化；刷新该线程及未读汇总。 | 机器人线程带 id；null 专指 team。 |
| inbox | 收件箱新建、回答、审批、到期、关闭；刷新 inbox 及总览数量。 | 机器人项带 id；中心项 null。 |
| activity | 回合、交账、审批、告警、协作、生命周期、启停；刷新 activity。 | 相关机器人必带；全局 null。 |
| settings | 主人修改全局设置；刷新 settings。 | null。 |

core 所有 emit 均改用常量，同一入口按 scope+botId 合并通知。全局规矩/设置/额度导致多机器人详情变化时逐个发 bot，不使用 `bot:null`。宿主模型目录为异步拉取接口，没有新增模型目录订阅能力；设置视图每次调用读取最新目录。

插件订阅者应按上述范围重取受影响视图，并在异步刷新回调中捕获错误。不要再匹配内部表名 `bots/wakes/watches/appraisals/queue`。

### 5. 宿主模型目录

```ts
interface HubModelOption { provider: string; model: string; label: string }
type ListModels = () => Promise<HubModelOption[]>;
// HubDeps 新增：listModels?: ListModels

const hub = createHub({
  ...deps,
  listModels: async () => hostModelRows.map(row => ({
    provider: row.provider, model: row.model, label: row.label,
  })),
});

// 接口变化：settings 从同步视图改为异步视图，插件需要 await。
hub.api.settings(): Promise<SettingsView>;
const settingsView = await hub.api.settings();
await hub.api.createBot({ ...profile, model: settingsView.modelOptions[1]!.value });
await hub.api.updateBot(botId, { model: { provider, model } });
```

宿主回调只提供可路由模型的三个字符串，不传凭据。目录按 provider/model 去重、保留宿主 label，并添加 `value:null` 的“跟随宿主默认模型”。有目录时，不把旧存档里已经下架的模型混进可选项。

新建/编辑均在写入前核对最终 provider/model；不在目录中返回中文错误。新建省略 model 时校验并继承 Settings.defaultModel；显式 null 始终跟随宿主默认。更新 Settings.defaultModel 同样校验目录。编辑期间等待目录不覆盖打断后的新运行态、会话解绑、暂停/退役或运行计数。

无 listModels 时保留原选项来源（null、设置默认值、名册已选模型）及自定义模型行为，但读取 settings 仍需 await。目录回调失败或返回非法数据时，视图抛中文错误，指定模型的写入返回失败；不把目录故障当成允许任意模型。null 不依赖目录校验。
