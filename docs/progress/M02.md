## 第三部分：敏感读取与实际执行入口

`gate/paths.ts`、`classify.ts`、`commands.ts` 将指定敏感目录/文件无论读写、工具名称或命令参数统一 protected，程序路径、附着短选项、上传 @ 路径、重定向也检查；env/printenv/set 输出环境至少 C。未知工具有明确敏感 path 也不能降为普通 C。

`m02-gate-security.test.ts` 的 `读文件工具拒绝 %s`、`bash 拒绝 %s` 对 16 类敏感路径各提供双入口；`%s 保持 protected` 覆盖 `$HOME`、`${HOME}`、`$DSH_HOME`、相对 cwd/父目录和附着参数；`%s 输出环境需审批`、`未知变量与 ~user 不当只读，公开普通文件仍允许` 保留 C 与 A 正反例；`敏感读守卫拒绝并计越界，不生成批准票` 验证真实守卫 protected、violations 加 1、无审批票。所有路径内容仅为测试夹具，没有接触实际凭据。

直接由中心 I/O 执行的关注项也纳入边界：新增 `perception/access.ts`，file/log 创建、更新和实际读取先检查；目录关注跳过敏感子树；http/rss 拒绝全部非 HTTP(S) 协议，敏感 file URL 先识别 protected；script 在 ExecIO 前复用 classifyArgv 检查参数、程序与 cwd 的 protected/work_data。

新增回归：

- `m02-perception.test.ts`：`中心直接执行的脚本关注也拒绝敏感参数 %s`（4 类参数）；`脚本关注在每次执行前复核工作数据授权，已授权只读仍可执行`。拒绝发生于 ExecIO 前，正常授权正例仍运行。
- `m02-watch-access.test.ts`：`%s 的机器人提议、重新启用与主人创建修改都拒绝敏感路径`（file/log）；`旧持久化 %s 敏感关注在实际读文件前暂停，不能因旧记录而放行`；`目录关注继续读取公开文件，但不触碰其中的敏感子树`。公开目录内容仍可读取，敏感内容不交给 FsIO。

## 七天快照与验证过程

调度修复（时间主体唯一化、最高优先级来源合并、交账清旧队列）、额度窗口恢复与真实 woke 解释日志改变了可重放事件序列。仿真世界事件与记录 id 使用同一随机源，因此增加审计记录也会改变后续注入的具体对象和次数；这些精确计数不能作为修复前后效果提升的因果比较。
