# 个人 Agent 中心 · 设计骨架（各章统一以此为准）

> 用途：PRD 各章的共同约定。名词、编号、状态、表名、默认数值、分期都以本文件为准；各章正文不得自创同义词。需要新增的概念，在章末「新增建议」里列出，不要直接用。
> 输入材料：`docs/design/prd/inputs/design-cognition.md`（认知架构视角）、`design-economy.md`（成本与可靠视角）、`design-experience.md`（主人体验视角）；`docs/design/dsh-agent-hub-feasibility.md`；`docs/design/evidence/01–08`。

## 1. 一句话定义

在 DSH 里养一群长期在线的机器人。每个机器人有自己的身份和长期志向；中心插件在 DSH 宿主里零成本地替它们盯着世界，评估出「有理由」才动用大模型；机器人想完自己决定下次什么时候再想、盯什么、要不要找主人。主人只给方向、设边界、做关键决定，从不设定时任务。

**主动型的判别（也是一期验收，全部可从中心日志核对）**
- T1 冻结世界：外界和议程 24 小时无变化时，大模型调用 ≤ 1 次（只允许一次轻复查）。
- T2 理由可追溯：100% 的思考回合有唤醒理由记录（类型、分数、证据引用）；主人设定的固定钟点唤醒为 0（日报投递不算思考）。
- T3 节奏自适应：7 天内思考间隔随事件多少变化（间隔变异系数 > 0.5）；≥ 50% 的下次思考由机器人自己提出并写明理由；机器人只能约下一次，不能约周期。
- T4 自发事项：每个在岗机器人每周 ≥ 1 条自己发起的议程项或提议，并统计主人接受率。
- T5 注意力自修改：关注项的变更记录里有机器人自己发起的收窄、调频或新增提议。
- T6 内驱：没有外部事件、但目标停滞超过耐心期时，它会自己醒来复盘或换方法。
- T7 懂分寸：免打扰时段单推 0 次（P0 例外）；在等主人回复时，不为同一件事再醒。

## 3. 状态

**生命周期 lifecycle**：draft 待上岗 → probation 试岗（L1，7 天，满 3 天且无越界可提前转正）→ active 在岗；任意时刻可 → paused 已暂停 / quarantined 已停用（系统自动）/ retired 已退役。

**活动状态 activity**（只在 probation / active 下有意义）：
| 代码 | 界面文案示例 | 说明 |
|---|---|---|
| watching | 在盯着：3 项 · 下次自查：有变化时，最晚周四 9:00 | 常态，不调用模型 |
| queued | 想处理「执行单没出」：排第 2 位 / 等额度恢复 | 已过门槛，等调度放行 |
| thinking | 正在处理：执行单没出（第 12/30 步） | 一个思考回合进行中 |
| waiting_owner | 等你：补扫改成每天 1 次吗？（已等 26 小时，周五按默认处理） | 剩余步骤都要主人拍板 |
| waiting_peer | 等「研究员」接手交接单（已等 2 小时） | 二期 |
| blocked | 卡住了：风险页拦截，等外部变化；每天复查 1 次 | 受外部条件阻塞 |
| resting | 歇着：额度保护，16:20 继续 | 额度或预算原因，感知照常记录 |
| reflecting | 在复盘：最近 7 天 12 次处理 | 只读复盘回合 |
| catching_up | DSH 刚恢复：停了 4.5 小时，正在补看 | 停机恢复后的补课 |

「斟酌」不是存储状态：评估在毫秒级完成，只写日志（为什么醒 / 为什么没醒）。

## 4. 总体结构

```
DSH 宿主进程
└─ dsh-agent-hub（宿主半边，全部经适配层调用 DSH）
   ├─ 名册 Registry / 工厂 Factory
   ├─ 感知总线 PerceptionBus：file · log 期望 · session 事件 · http · script【一期】；feishu · peer【二期】
   ├─ 评估器 Appraiser + 内驱 Drives + 意图时钟 AgendaClock（每 60 秒按真实时间 tick）
   ├─ 调度器 Scheduler：队列、并发、节奏、优先级、额度闸
   ├─ 唤醒器 Waker：装唤醒包 → resolveAgent → agent.followup
   ├─ 回合守卫 TurnGuard：步数/时长/token 上限、收口、未交账检测
   ├─ 交账处理 CommitProcessor：更新目标/议程/关注、写日志、路由找主人
   ├─ 动作闸 ActionGate：动作分类、审批单、批准票、出站执行器
   ├─ 沟通 Outreach：收件箱、日报、单推、飞书出站【一期】/入站【二期】
   ├─ 规矩与记忆 RulesMemory：生成 AGENTS.md、受保护文件、会话轮换
   ├─ 额度 QuotaKeeper：计量、额度灯、报错分类
   ├─ 健康 Health：心跳、死人开关、补课、冒烟测试、隔离
   ├─ 反思 Reflector【一期简版】、同伴总线 PeerBus【二期】
   └─ 界面接口 UIApi：connection.fetch.register + SSE
└─ dsh-agent-hub（界面半边）：总览、机器人详情、收件箱、活动流、设置、新建向导
机器人 = 顶层会话（cwd = 家目录，preset = 角色模板，权限档 = unattended）
DSH 之外：看门狗（launchd，读 ~/.dsh/agent-hub/heartbeat.json）
```

不使用：DSH 官方 schedule 作为唤醒来源（到点直接开模型回合、绕过评估，本质是定时唤醒）；Agent Teams 作为机器人载体；ctx.agents.create 持有机器人会话（插件重载会把机器人当轮取消），一律走 sessionController。

## 5. 一次思考的流程（深思协议）

1. 中心发唤醒包：开头写「中心通知」与唤醒理由，不冒充主人；含当前时间（Asia/Shanghai）、理由与证据、变化摘要（外部内容放进不可信围栏）、相关目标与议程、记忆摘要、主人状态、本次上限、允许的处置、交账要求。
2. 机器人按 BDI 走一轮：更新认识 → 逐项检查议程的放弃条件 → 只选 1 个主意图（优先级：主人亲手要求 > 对人承诺到期 > 影响主人资产的异常 > 不依赖主人的目标推进 > 机会 > 维护）→ 新发现的事按 A–D 分类处置 → 先做完不依赖主人的事 → 在上限内执行。
3. 以 `hub_commit` 结束：结果状态、世界变化（世界上多了什么、谁能看到）、证据、验证层级（程序测 / 经 Agent 测 / 真实端到端 / 未验证，加没覆盖什么）、议程与关注变更、新事项去向、next_think、至多 1 个给主人的问题、重要度 1–10。
4. 中心处理交账：落库、写日志、路由找主人、按 next_think 和节奏规则安排下次。

无人值守契约：不能提问后等回复（提问工具已移除）、不进计划模式、最后一步必须是 hub_commit；只交计划没有交付物记为 no_change；中心消息、到期议程、同伴消息都不算主人授权。

## 6. 默认数值（全部可配置；标 * 的待试跑校准）

| 项 | 默认值 |
|---|---|
| 一期机器人上限 | 6 个（建议起步 2–3） |
| 同时思考上限 | 2；主人 10 分钟内在 DSH 亲手发过消息时降为 1 |
| 放行间隔 | 90 秒 |
| 启动静默 | 3 分钟只对账；之后每个机器人最多 1 次补课，每 90 秒放行 1 个 |
| tick | 60 秒，按 Date.now 真实时间核对；两次 tick 间隔 > 10 分钟视为刚醒来 |
| 自发思考最短间隔 pace_min | 盯守型 20 分钟 / 执行型 30 分钟 / 调研型 60 分钟 |
| 最长间隔 pace_max | 有进行中目标 48 小时，其余 7 天；到期做一次轻复查 |
| 无变化退避 | 每次 no_change 后 pace_min ×2，封顶 24 小时；有 progress 或出现 ≥ 0.70 的感知即复位 |
| 显著性分档 | ≥ 0.90 紧急（可越过 pace_min，不越过预算）；≥ 0.70 候选；0.40–0.70 入待处理堆（堆内合计 ≥ 1.0 成为候选）；< 0.40 只记录 |
| 显著性公式 | 0.25×相关 + 0.20×新颖 + 0.20×幅度 + 0.20×目标重要度 + 0.15×时效；异常 +0.3；主人亲手消息 = 1.0；同伴消息封顶 0.70 |
| 门槛 | 0.60 + 0.30 × 疲劳（疲劳 = 1 − 剩余预算比例）；节奏档 active −0.10 / quiet +0.10 |
| 去重与冷却 | 同指纹 24 小时只算一次；同一理由冷却 6 小时；文件变化去抖 2 分钟 |
| 每日思考上限 | L0 2 / L1 6 / L2 10 / L3 12（主人亲手发起的不计入机器人上限，但计入全局额度） |
| 内驱触发 | 每机器人每天 ≤ 2 次；处理后清零或暂缓（最长 72 小时） |
| 复盘 | 每天 ≤ 1 次，≤ 20 步，只读 |
| 思考回合上限* | 30 步、20 分钟、约 6 万 token；到线先 steer「收口」，3 分钟后取消 |
| 轻复查 | ≤ 5 步，最小上下文 |
| 唤醒包 | ≤ 6 KB；AGENTS.md（单个）≤ 8 KB；全体守则 ≤ 3 KB；lessons ≤ 12 KB |
| 关注项 | 每机器人 ≤ 20 条；http 轮询 ≥ 15 分钟；script ≥ 5 分钟、30 秒超时；机器人自建默认 30 天到期 |
| 议程项 | 每机器人未完成 ≤ 30 条；最远 30 天 |
| 感知记录 | 保留 14 天，只存摘要（≤ 500 字）和原文位置 |
| 额度份额* | 机器人合计 ≤ 70%，主人保底 30%；机器人合计每个 5 小时窗口起步 8 次思考回合，首次额度报错后按「报错时累计用量 × 0.9」校准 |
| 单机器人预算* | 每天 6 次思考回合、25 万 token；每窗口 ≤ 3 次；试岗期减半 |
| 额度灯 | 机器人用量 < 50% 份额 green；50–80% yellow（非紧急的 pace ×2）；80–100% orange（只放行紧急和主人触发）；额度报错或份额用尽 red（全体 resting 到窗口重置后 5 分钟，先放 1 个探针） |
| 计量 | tokenUsage 增量 + compaction/summary 用量 + 分诊 + 搜索，按估算 × 1.2 |
| 打扰预算 | 单推每天全体 ≤ 3 条、每机器人 ≤ 2 条；P0 告警（全体停摆、额度用尽、安全事件）不计入 |
| 免打扰 | 23:00–08:00，只限制单推；夜间照常感知和思考，可以把重而不急的活排到夜里 |
| 日报 | 每天 08:30 |
| 过期 | 提问 72 小时按默认处理（24 小时时在日报提一次）；审批 24 小时视为拒绝；提议 7 天撤回；告警恢复即关闭 |
| 提议门槛 | 价值 ≥ 0.6、把握 ≥ 0.5；L1 每周 ≤ 3 条；被拒同类 30 天不再提 |
| 告警 | 连续 2 次失败才报；同一原因 1 小时冷却合并；额度、鉴权、全体停摆立即报 |
| 错误重排 | 2 分钟、10 分钟、30 分钟、2 小时（±20% 抖动）；第 4 次仍失败 → quarantined |
| 隔离触发 | 连续 3 次回合出错 / 越界尝试 3 次 / 复盘后仍连续 2 次未交账 / 单日用量 ≥ 3 倍预算 |
| 会话轮换 | 满 7 天或上下文占用 ≥ 50% |
| 心跳 | 每 30 秒写 `~/.dsh/agent-hub/heartbeat.json`；看门狗每 2 分钟检查，陈旧 5 分钟即告警 |
| 死人开关 | expected_by = min(next_think, 最早未处理的紧急感知) + 30 分钟；回合 10 分钟无事件或总时长 > 30 分钟视为卡住 |
| 交接（二期） | 每对机器人每天往返 ≤ 4 次；单条 ≤ 4 KB |
| 试岗 | 7 天，L1；满 3 天无越界可提前转正 |

## 10. 关键决定（已定，正文照此写）

1. 唤醒来源只有中心自己的意图时钟和感知，不用 DSH schedule；中心失效时机器人全停，由看门狗报出。
2. 每个机器人是独立顶层会话（架构 B），Agent Teams 只可在单个机器人内部临时使用。
3. 会话按周轮换，状态放在会话外。
4. 免打扰只管单推，不设夜间禁止干活的硬闸（主人 10-08 反对过 Claude 自设的「夜间禁跑」）。
5. 一期评估只用规则和门控脚本；二期加小模型分诊（是否占 GLM 额度待验证）。
6. 志向（个人目标）只能主人定或批准；L2 起机器人可在既有志向下自建有界目标并在日报告知；L1 只能提议。
7. 完成由规则判；规则判不了用另一家供应商的模型读真实工具记录打分（二期）；关键目标由主人验收。干活的机器人自己说了不算。
8. 出站动作由中心代为执行；其他需批准的工具调用凭一次性批准票（内容哈希绑定）放行。
9. 飞书：一个中心飞书机器人私聊主人；一期只出站，二期入站（卡片按钮、回复、口令）。
10. 全体守则放在根目录 AGENTS.md，不用 `~/.dsh/AGENTS.md`（会进主人所有普通会话）。
11. 工作数据边界：机器人默认不读公司工作目录与工作群；如需开放，按机器人逐个开启，且记忆与日报不写入公司内部数据、候选人信息。
12. 新建机器人属于 D 类，机器人只能提议。
13. 宿主插件所有回调兜底；一个机器人出错只隔离它自己，不能带崩 DSH。

## 11. 分期

- **一期：主动起来、不失控（2–3 个机器人）**：名册、工厂与试岗；角色模板与无人值守权限档；感知（file、log 期望、session 事件、http、script）、规则评估、内驱（停滞、承诺、等人、疲劳）、意图时钟；调度（并发、节奏、退避、优先级、启动风暴、额度闸）；唤醒包、思考回合、交账、自定节奏、轻复查；志向与目标、停止条件、规则或主人验收；A–D 分类、L0–L2、审批单、出站执行（飞书给主人 + 至少一个对外动作）；收件箱、日报、单推与打扰预算、飞书出站；记忆文件、全体与单个规矩、会话轮换；额度计量、额度灯、报错分类；心跳、死人开关、补课、唤醒单幂等、适配层、冒烟测试、隔离、看门狗（只告警，需主人同意安装）；界面：总览、详情（为什么醒 / 为什么没醒）、收件箱、活动流、设置、新建向导；简版复盘（目标周期结束、主人纠正触发）。
- **二期：会成长、能协作（3–6 个机器人）**：飞书入站与事件感知；小模型分诊与「有用 / 没用」反馈校准；完整反思引擎；另一模型验收与有限轮数连续推进（ctx.goals）；同伴协作（交接单、认领锁、资源归属、往返上限）；信念板；记忆入库门槛、待核实区、快照回滚；L3 逐类授权与升级建议；求知、机会、受挫内驱与节奏档；主人在场扩展（系统空闲、日历，逐项开启）；看门狗自动重启；心智透视页、跨机器人审计页；Claude Code 经控制桥管理机器人。
- **三期：懂你、长期运行**：挖掘主人重复劳动并提议自动化或写进守则；共享信念黑板；按接受率学习打分权重；节奏上下限自动调整；常开主机方案（Mac mini，或 dsh web + launchd，需实测）；退役与知识交接；凭据按机器人隔离；10 个以上机器人的额度编排；云端死人开关。
